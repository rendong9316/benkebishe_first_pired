## 一、项目进展概述

在单目标UKF滤波（PDA栅格加权 + 模糊自适应Q）基础上，完成了多目标仿真场景构建与多航迹跟踪管理器的实现。参考 `myOTHR/mainTrackingEngine.m` 架构，融合UKF双基地量测模型的优势，最终实现两部雷达各自稳定追踪3架飞机的全部航迹。

### 架构设计

每帧处理流程（`multi_track_manager.m`）：

```
输入: trackList, tempPool, detList, ukf_tpl, params, frame_id
  │
  ├─ Step 1: 分离活跃航迹 (RELIABLE/MAINTAIN/TEMPORARY) 与历史航迹 (HISTORY)
  │
  ├─ Step 2: 无活跃航迹 → 直接起始（track_starter_mofn）
  │
  ├─ Step 3: 批量UKF预测所有活跃航迹
  │    └─ 每航迹独立计算 x_pred, P_pred, X_pred, z_pred, P_zz
  │
  ├─ Step 4: JNN全局点迹-航迹关联
  │    └─ 构建全局代价矩阵 → 贪心最小代价分配 → 保证1点1航迹
  │
  ├─ Step 5: 更新关联航迹（UKF更新 + PDA栅格加权 + 模糊自适应Q）
  │
  ├─ Step 6: 更新未关联航迹（纯预测，missed++）
  │
  ├─ Step 7: 质量状态机打分 + 状态转移
  │
  ├─ Step 8: 未使用点迹 → M/N起始新航迹
  │
输出: trackList, tempPool, trackSnapshot
```

## 三、关键问题与解决方案

### 问题1：航迹中断振荡

**现象**：RELIABLE 航迹在 RELIABLE ↔ MAINTAIN 之间剧烈振荡，最终质量崩盘变成 HISTORY。

**根因**：质量计分系统不对称——RELIABLE 漏检一次 -2 分立即降为 MAINTAIN，关联成功仅 +1 分。Pd=60% 场景下连续漏 2 帧概率 16%，直接 -4 分崩盘。

**解决**（`manage_track_quality.m`）：

```
修复前: RELIABLE 漏检 → quality-2 → 立即降 MAINTAIN
        MAINTAIN 漏检 → quality-2 → <5 降 HISTORY
修复后: RELIABLE 漏检 → quality-1 → <8 降 MAINTAIN
        MAINTAIN 漏检 → quality-1 → <3 降 HISTORY
```

对称计分使 quality 缓慢波动而非剧烈跳变，成熟航迹不再因暂时漏检而死亡。

### 问题2：追踪不全（部分飞机无法起始）

**现象**：R1 仅追踪 1-2 架飞机，R2 追踪 2 架。第 3 架飞机迟迟无法起始航迹。

**根因**：M=3/N=5 窗口过窄。Pd=60% 下 5 帧内累积 ≥3 次检出的概率仅 68%，某些飞机因随机分布无法满足条件。

**解决**（`simulation_params.m`）：

```
M=3/N=5 → M=3/N=7
P(≥3次检出) = 68% → 90%
```

放宽时间窗口给稀疏检出的飞机更多累积机会。

### 问题3：成熟航迹被 K_loss 强行终止

**现象**：已追踪 24+ 帧的高质量航迹因连续漏检被 K_loss=4 强制杀死。

**根因**：K_loss 对所有航迹类型无差别生效。Pd=60% 下 0.4⁴ = 2.5%，57 帧中几乎必然触发。

**解决**（`manage_track_quality.m`）：K_loss 仅对 TEMPORARY 航迹生效。RELIABLE/MAINTAIN 航迹靠质量积分自然衰减，不再被硬阈值误杀。

### 问题4：逐航迹 NN 先到先得

**现象**：第一条航迹抢走其他飞机点迹，后处理航迹饿死。

**根因**：逐航迹最近邻按循环顺序处理，航迹按 active_idx 排列，先处理的航迹有机会选中不属于自己的点迹。

**解决**（`jnn_association.m`）：改为 JNN 全局贪心分配：

```
构建全局代价矩阵 C(i,j) = 马氏距离(航迹i, 点迹j)
while 存在合法对:
    选取 C 中全局最小代价对 (i*, j*)
    分配: 航迹i* ← 点迹j*
    移除第i*行和第j*列
```

保证全局最优匹配，不受航迹处理顺序影响。

### 问题5：假航迹泛滥

**现象**：M=2 时产生 14+16 条航迹，大量杂波序列通过 M/N 条件。

**根因**：候选点迹序列未经运动一致性验证，杂波的随机分布恰满足 M/N 计数即起航。

**解决**（`track_starter_mofn.m`）：候选验证函数 `validate_candidate_sequence`：

- Robust regression 拟合 lon = f(lat) 直线
- 最大残差 < 50km（点迹基本共线）
- 若总跨度 > 100km，要求残差 < 跨度的 40%（防随机游走）
- 总跨度 > 500km 拒绝（单帧不可能）

### 问题6：UKF 预测漂移导致永久失联

**现象**：连续漏检后 UKF 纯预测逐步漂移，真值点迹落入地理门外，形成"越漏越偏→越偏越漏"的正反馈。

**根因**：固定地理门在连续漏检时不扩大，UKF 纯预测无测量修正，漂移积累。

**解决**（`jnn_association.m` + `multi_track_manager.m`）：自适应动态地理门：

```
早期(≤15帧): 120km（UKF未收敛，不确定性大）
成熟期:      80km（UKF已收敛，可区分不同飞机）
连续漏检:    +15km × missed_frames（防漂移后失联）
```


两部雷达均稳定追踪全部3架飞机。航迹连续无中断，假航迹均在10帧内自动终止。

## 六、仍存在的局限

1. **R2 第三条航迹起始偏晚**（life=23，约帧34起始）。飞机C的横穿航线在R2视角下点迹分布较稀疏。

2. **单 seed 验证**。仅 seed=42 一组结果，不同随机种子下表现可能有统计波动。

3. **HISTORY 航迹不恢复**。一旦进入 HISTORY 状态永久休眠，无法在目标重新出现时复活。

4. **航迹匹配尚未实现**。两部雷达的 RELIABLE 航迹各自独立，尚未做"谁对应谁"的航迹关联。
